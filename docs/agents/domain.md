# 领域文档使用规则

本仓库采用 single-context 结构。

## 开始探索前

处理涉及产品概念、内容模型或架构决策的任务前：

1. 阅读根目录 `CONTEXT.md`
2. 阅读 `docs/adr/` 中与当前任务相关的 ADR
3. 如果文件不存在，继续工作，不将缺失本身视为阻塞

## 文件结构

```text
/
├── CONTEXT.md
├── docs/
│   ├── adr/
│   └── agents/
└── src/
```

## 术语规则

- 需求、issue、测试和代码注释中的领域概念应使用 `CONTEXT.md` 定义的术语。
- 不应为已经定义的概念随意创造同义词。
- 如果确实缺少必要概念，应记录为领域模型待补项。

## ADR 冲突

如果拟议修改与现有 ADR 冲突，必须明确指出对应 ADR 和冲突内容，不能静默覆盖既有决策。
